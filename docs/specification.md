# 仕様書

全データは架空です。テーブルの詳細は [ER図](er.md)、書き方の決まりは [コーディング規約](coding_guidelines.md) を見てください。

## 1. 目的
外国人スタッフを受け入れている中小企業の総務担当者が、スタッフごとの在留期限・在留資格・提出書類の状態を一か所で管理し、期限切れや出し忘れを防ぐ。複数の会社（または拠点）が同じシステムを使っても、データが混ざらないようにする。

## 2. 解決したい課題（想定した現状の業務）
| 今の業務（架空の想定） | 起きていること | このアプリでの置き換え |
|---|---|---|
| Excel台帳にスタッフと在留期限を手入力 | 期限が近づいても気づかない | ダッシュボードで90／60／30日・期限切れを色と文字で表示 |
| 月1回、台帳を目で見て期限を確認 | 月の途中で期限を迎える人を見落とす | 毎日の期限チェックで通知を自動作成 |
| 書類（パスポート写し・雇用契約書など）を紙とフォルダで管理 | 出し忘れ・更新忘れ | 書類チェックリストで状態を管理、期限切れを自動判定 |
| 拠点や会社ごとの台帳を共有フォルダに置く | 他の拠点・会社の個人情報が見えてしまう | 組織単位でデータを完全に分ける |
| 届出用の一覧を台帳から手で作る | 転記ミス、和暦・西暦の書き換えの手間 | 提出用CSVとPDFを出力 |
| 誰が台帳を直したか分からない | 間違いの原因が追えない | 監査ログに操作者・日時・変更内容を残す |

## 3. 利用者と権限
| 操作 | 管理者（admin） | 担当者（member） | 未ログイン |
|---|---|---|---|
| ダッシュボード・スタッフ・書類の閲覧と更新 | ○ | ○ | ログイン画面へ |
| 在留期限一覧PDF | ○ | ○ | ログイン画面へ |
| 提出用CSV | ○ | ×（403） | ログイン画面へ |
| ユーザー・書類種別・組織名の設定 | ○ | ×（403） | ログイン画面へ |
| 期限チェックの「今すぐ実行」 | ○ | ×（403） | ログイン画面へ |
| 他の組織のデータ | ×（404） | ×（404） | ログイン画面へ |

- 他組織のデータは「存在しない」扱いの404にして、存在そのものを漏らさない。自組織の画面で権限が無い場合は403。
- 管理者は自分自身の権限変更と削除はできない（管理者が誰もいなくなる事故を防ぐ）。

## 4. 画面
1. ログイン
2. ダッシュボード（指標4つ、期限の近い順の一覧）
3. スタッフ一覧（検索・在留資格／在籍状態で絞り込み）、詳細（在留カード履歴・書類へのリンク）、登録・編集
4. 在留カードの追加（履歴として追加のみ。編集・削除はしない）
5. 書類チェックリスト（スタッフごと）
6. 通知一覧（送信予定メールのデモ表示つき）
7. 出力（PDF・CSV）
8. 組織設定（組織名・ユーザー・書類種別・今すぐ実行）
9. エラー画面（日本語の403／404／422／500）

すべての画面の上部に「架空のデータによるデモです」を表示する。

## 5. データの決まり
- 会社（組織）を持つテーブルはすべて `organization_id` を持ち、親子で組織が食い違うデータは保存できない。
- 社員コードは組織内で一意（別の組織なら同じコードでよい）。
- 在留カードは履歴として複数持ち、期限が最も新しい1枚を「現在のカード」とする。カード番号は下4桁だけ保存する。
- スタッフは削除せず、退職は状態を「退職」にする。
- 書類の状態遷移：未提出 → 提出済み（提出日が必須）→ 承認済み。差し戻し（提出済み → 未提出）と再提出（承認済み・期限切れ → 提出済み）を許す。「期限切れ」は人が付けず、毎日のチェックだけが付ける。
- 書類の有効期限は、空なら「提出日＋書類種別の更新間隔（月）」を自動で入れる。
- 状態などの区分は文字列＋データベースの CHECK 制約で守る。

## 6. 期限の区分
| 残日数 | 区分 | 表示 |
|---|---|---|
| 0日未満 | 期限切れ | 赤＋「期限切れ」 |
| 0〜30日 | 30日以内 | 文字ラベル併記 |
| 31〜60日 | 60日以内 | 文字ラベル併記 |
| 61〜90日 | 90日以内 | 文字ラベル併記 |
| 91日以上 | 対象外 | 表示なし |

色だけに頼らず、必ず文字ラベルを付ける。「今日」は日本時間で判定する。

## 7. 毎日の期限チェック
- 在籍中のスタッフの現在の在留カードについて、その時点で最も厳しい区分の通知を1件作る。同じカード・同じ区分の通知は1件だけ（同じ日に何度動かしても増えない）。
- 有効期限を過ぎた書類を「期限切れ」にする。
- ジョブとして動かすときは失敗したら3回まで再試行し、それでも失敗したら監査ログとログに記録する。「今すぐ実行」とコマンドでは再試行せず、失敗をその場で記録して表示する。
- 起動時に1回、管理者画面の「今すぐ実行」、コマンド `ruby bin/rails zairyu:daily` で動かす。

## 8. 出力
- **在留期限一覧PDF**：A4横、組織名・出力日、在籍スタッフを期限の昇順で。日本語フォントを同梱。カード番号は載せない。
- **提出用CSV**：公的な届出の項目並びを参考にした独自様式。Shift_JIS（既定、Excelでそのまま開ける）または UTF-8（BOM付き）、西暦または和暦。改行は CRLF。先頭が `= + - @` のセルは無害化する（CSVインジェクション対策）。
- どちらも「架空のデータによるデモです」「行政の正式様式ではありません」を明記する。

## 9. 運用面
- `/up` でヘルスチェック（ログイン不要）。
- ログの各行にリクエストIDと組織IDを付ける。氏名・生年月日・カード番号はログでは伏せ字にする。

## 10. 今回やらないこと
- 本番サーバーでの公開、メールの実配信、決済、パスワード再設定。
- 行政の正式様式の完全な再現。
- お知らせ文のAI下書き（やさしい日本語化・翻訳）。仕様の検討はしたが、期限内に品質を確保できる範囲を優先して外した。
- 常駐のジョブ基盤（Windows で動かないため、起動時と手動実行で代替）。

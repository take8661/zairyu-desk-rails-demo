# レビュー・設計判断の記録

全データは架空です。

## 設計判断
- `/reports`：admin・member とも閲覧可。CSV のリンクと取得は admin のみ。
- 書類種別の削除：未提出（missing）の行だけが紐づく場合は紐づく行ごと削除。それ以外が紐づくときは削除を拒否（422）。
- スタッフ作成時に在留カードを最低1枚必須（作成時の検証）。
- デモデータ（seeds）は `find_or_create_by` 系のみで、既存データを更新しない。
- 定期実行は Solid Queue を使わず、起動時1回・画面の「今すぐ実行」・rake タスクで代替（Windows で fork モードが使えないため）。

## 実測した検証
- `bundle exec rspec`：285 examples, 0 failures。行カバレッジ 99.10%（771 / 778）。
- `bundle exec rubocop`：116 files inspected, no offenses detected。
- 日本語を含むフォルダでは、メインスクリプトとして起動した `ruby bin/rails` が `__dir__` の文字化けで失敗する（`bundle exec rspec` は動作）。英数字だけのパスなら動く想定で、起動手順に明記した。

## 実装中に見つけた不具合と対応
- 書類の不正な状態遷移（未提出 → 承認済み）で422を返しても、エラーメッセージが画面に出なかった。再読込した別オブジェクトにエラーが載っていたため。エラーを持つレコードを一覧に差し替えて修正し、テストで固定した。
- テスト側の不備：ヘルパーの `deep_merge` が内側にしか効かず「必須項目が空」のテストが空振りしていた／CSV の Content-Type の大文字小文字／通知テストのデータ作成順。いずれもテストを直した（検査を削って通したものはない）。
